# Branching

La estrategia de ramas visible en este repositorio es básica y orientada a trabajo incremental.

## Estado real

- Se trabaja con ramas de tipo feature para cambios concretos.
- No se observa un Git Flow completo ni una política formal documentada para releases, hotfixes o develop.
- La trazabilidad depende de commits y ramas descriptivas.

## Criterio recomendado

Para una evolución más ordenada, la opción más simple es GitHub Flow. Si el equipo requiere más control de versiones, puede adoptarse Git Flow.

## Buenas prácticas actuales

- Usar ramas cortas y descriptivas.
- Mantener commits pequeños y trazables.
- Relacionar cada cambio con su propósito funcional.

## Mejora futura

- Formalizar una convención de nombres para ramas y commits.
- Definir flujo de integración y revisión por pull request.
- Documentar la política de merge y publicación.
